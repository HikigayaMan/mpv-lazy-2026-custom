# 2026-10-12 网页与 MPV 双向续播验证

## 实现及安装

当前源码用户脚本为 External Player 1.2.14.19，中继为 2026.10.12。修复包括双向本机保存、B站账号历史、分 P 隔离、切品质保留进度、HTTP 传输兜底及 MPV 参数解析。已导入 .18 的浏览器使用新 Lua 的精确旧格式兼容，无需再次导入；.19 使用两个独立 `--script-opts-append`。

已安装到用户的现有 MPV 运行包，中继只在没有活动会话时更新，安装前后校验 46 个偏好／历史文件保持一致。账户认证只在浏览器使用，运行状态不会进入更新包。本次变更整合为 `v2026.10.12-progress-update` 累计 Release；先前的 `v2026.10.12-update` Release 内容保持原样。

## 真实 B站测试

使用普通投稿视频 `BV1U3p86dExt`，用户保持登录并启用双向同步和账号历史写入。

| 检查 | 实测 |
| --- | --- |
| 网页 → MPV | 网页暂停在约 153.29 秒，交接使用最近保存的约 153.03 秒；MPV 开始后继续播放，IPC 确认已建立相同内容的有效进度快照。 |
| 播放器模式 | 1920×1080，自动全屏。 |
| MPV → 原网页 | 通过测试播放器 IPC 暂停并精确跳转到 187.5 秒；原网页保持暂停，视频元素确认 currentTime = 187.5，UI 显示 03:08。 |
| MPV → B站账号历史 | 新开 B站官方历史页，测试视频的条目显示 03:07 / 06:20；这与账号接口使用整数秒一致。 |
| 退出后的本机保存 | 退出本次测试播放器，本机记录为 187.5 秒、source=mpv、completed=false。 |
| 刷新网页续播 | 原网页刷新后从保存的位置继续播放；稍后暂停观察为约 229.10 秒，没有重新从零开始。 |

账号历史截图保存于本地构建输出的 `history-proof.jpg`，只截取测试视频条目，截图和账户运行状态不进入发布包。测试没有修改其他视频条目或用户其他浏览器页。

## 回归范围

- Node 用户脚本测试：87 项通过。
- 中继 Python 测试：原有 26 项、进度协议 24 项、HTTP 兜底 7 项通过。
- Lua／打包测试：150 项通过，包括原有 141 项、进度 Lua 8 项和新增的 HTTP 发布证明校验。
- 独立只读复审通过；覆盖请求顺序、失败启动清理、刷新接管旧页通知、ACK 中断清理和旧参数格式验证。
- 新冻结 EXE 在隔离端口通过 health、WebSocket hello 和匿名 HTTP 进度读请求，包含原生 Brotli，构建输入与源码校验一致。
- 实际 MPV／Windows IPC 冒烟验证 WebSocket 和 HTTP；HTTP 分别验证 .19 的两个 append 参数与 .18 合并参数兼容。覆盖 12.5 秒续播、后退到 7.25 与 0、23.9 秒切画质、浏览器断开后保存 31.875 秒、重新打开网页订阅、播放器重开续播、其他 CID 与换文件隔离。

浏览器实测验证了真实网页、当前 MPV 安装和账号历史；本地 HTTP 冒烟验证传输兜底，不等同于全部浏览器扩展组合。普通网站账号历史、直播续播、番剧影视和互动分支没有接入。账号历史写入依赖登录网页保持运行，网页关闭期间只保存本机位置。

MPV 参数语义参考 [官方手册的列表选项](https://mpv.io/manual/stable/#list-options)：`append` 追加单个项目，因此两个选项需要分别传入。

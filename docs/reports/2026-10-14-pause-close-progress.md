# MPV 暂停／关闭时更新网页进度

日期：2026-10-14。当前源码用户脚本版本：**External Player 1.2.14.26**。

本次调整响应“MPV 暂停或关闭时再更新 B站原网页进度”的需求。MPV 播放中不再持续修改原网页播放器的位置，本机续播和 B站账号观看历史继续保存。此前 .24 的清理、完整合集快启及真实 325 视频合集耗时，保留在 [原验证报告](./2026-10-14-cleanup-and-fast-start.md)，不作为本次 .26 的新验证结论。

## 最终行为

| MPV／网页操作 | 原网页播放位置 | 本机续播／B站账号历史 |
|---|---|---|
| MPV 正常播放、恢复播放 | 保持原位置 | 继续保存；账号历史约 15 秒一次 |
| MPV 播放中拖动进度 | 保持原位置 | 保存新的实际位置 |
| MPV 暂停 | 更新至暂停位置 | 保存暂停位置 |
| MPV 暂停中拖动进度 | 更新至新的暂停位置 | 保存新位置 |
| MPV 快速暂停后立即继续 | 保留暂停时的更新；恢复播放不追加跳转 | 继续保存 |
| MPV 正常关闭 | 更新至退出快照／最近成功采样的位置 | 保存该位置，不误标完成 |
| MPV 播到片尾、换集、循环或品质重载 | 不把这些操作当成关闭，不因此更新网页 | 按原内容身份保存；实际 EOF 才按看完处理 |
| 网页刷新、视频 DOM 替换或中继重连 | 不回放正在播放的 MPV 缓存位置 | 记录仍可用于本机续播和账号历史 |
| 网页自动播放或自动恢复位置 | 不视为用户接管，不覆盖 MPV 会话 | 保留当前 MPV 续播记录 |
| 用户主动在网页播放或拖动 | 网页取得记录控制权，旧 MPV／旧连接不覆盖 | 保存网页实际观看位置 |

关闭原网页后，运行中的中继仍保存本机位置；浏览器关闭期间无法借用该登录会话写入 B站账号历史。网页重新打开后，MPV 仍在播放时不因缓存位置移动网页进度。暂停／关闭事件只应用到对应的视频与分 P。

正常退出识别 `quit`／`shutdown`，与 EOF、换文件和品质重载区分。进程关闭 IPC 早于退出快照采样时，使用中继最近一次成功采样；强制结束进程也无法保证取得最后一帧。正常采样间隔约 1 秒，实际误差另受请求与退出时序影响。

## 实现与兼容

- 用户脚本分别处理本机保存、账号历史写入和网页位置更新。播放采样仍可保存，只有暂停或关闭边界允许改变网页位置。
- Lua 快照保留暂停边界，最多 32 条；暂停后立即继续也不会只剩“播放中”的最新采样。新中继通过可选 `pauseEventsApiVersion: 1` 协商读取，旧 Lua 普通快照仍兼容。
- 匿名 HTTP 通道最多 64 条事件队列合并普通进度更新并保留暂停／暂停中跳转边界，避免频繁播放采样挤掉一次暂停更新。WebSocket 使用相同的同步判定。
- 播放中缓存状态、网页刷新和中继重连不会替代一次有效的暂停／关闭事件，也不会撤销用户已经交回网页的控制权。
- 修复冷启动会话注册与初始化慢请求处理：注册会话前绑定当前页面标识，解析未结束时不重复重置状态。网页自动播放／自动恢复位置与真实用户操作分别判定：前者不接管 MPV，用户点击、拖动和播放／跳转快捷键仍可接管。
- 保留倒退、零秒、分 P 隔离、品质切换续播及按实际 EOF 标记看完的既有行为。Cookie、CSRF 和 WBI 密钥继续只在浏览器使用。

## 安装范围

需要一起更新：

1. `external_player.js` 及 `.26` 用户脚本；导入后禁用 .25 及其他重复旧版并完整刷新网页。
2. `portable_config/scripts/web_progress.lua`。
3. `tools/telegram-web-mpv-bridge/playback_progress.py`、配套中继源码及新构建的 `bilibili-live-bridge.exe`；重启本安装的旧中继和播放器。

已发布的 `.19` 累计 Release 仍可下载，但不包含本次同步时机调整；本报告不代表已创建新的 Release。操作说明见 [进度同步文档](../scripts/playback-progress.md)。

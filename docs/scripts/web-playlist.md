# 网页视频列表移交 MPV

本次 [v2026.10.14-update 累计 Release](https://github.com/HikigayaMan/mpv-lazy-2026-custom/releases/tag/v2026.10.14-update) 包含 External Player **1.2.14.26**、中继 **2026.10.14** 与配套播放器 Lua／uosc，支持 B站完整合集及分 P 的层级播放列表，以及当前视频快启、后台补齐合集。先前的 `.19` Release 不包含本功能；安装本次累计包即可一次更新本说明列出的文件，完整范围见 [发行说明](../releases/v2026.10.14-update.md)。

## 使用

在普通 BV／av 视频页点击 MPV 或 MPVNET：投稿属于合集时，将完整合集及其中各视频的全部 P 交给播放器；没有合集时交接当前视频的全部 P。相关推荐不进入列表，播放器从网页当前选中的具体 P 开始。

播放器先打开当前 CID，完整合集的分 P 详情在后台补齐，不必等待所有其他视频的详情请求。菜单此时显示合集名称与“合集加载中”，并注明“完整合集正在后台加载”；当前单条清单不会被标作完整合集的 `1/1`。后台成功后在同一个播放器中扩展完整原生列表，保留正在播放条目的原生 ID、位置、暂停、品质、音轨和弹幕，不重新加载当前视频。

完整清单就绪后，播放列表顶部显示合集名称与当前视频序号，下面按“分节（有多个分节时）→视频→分 P”排列。多 P 视频可在同一面板展开／收起，子视频缩进显示名称及时长；单 P 视频直接点击播放，不增加只有一项的子层。当前播放项的祖先在首次打开或切换播放项时自动展开，其余折叠选择保留。

使用播放器原有的播放列表入口选择条目，或点击上一条／下一条。展开／收起只改变显示，不删除实际视频。顺序播放依次走完整合集与各 P；乱序以可播放的具体 P 为单位；列表循环遍历整个合集，单曲循环重复当前 P。续播点只应用于首次加载，单曲循环重播完整视频。点选按实时原生条目 ID 查找，原生乱序后不会因界面行号变化而打开错误的视频。

每次实际播放条目时，通过原浏览器账号重新解析源，保持账号可用品质、独立音轨和字幕。切换画质时只重载当前条目，不清空整个列表。弹幕 CID、样式和开关按当前视频生效；旧条目的迟到弹幕请求不会覆盖新条目。

## 进度与浏览器

每个 `aid + cid` 分别保存位置。切换回未看完条目可续播，已完成条目从零开始；加载中的临时零秒不覆盖续播记录。已启用 B站账号历史时，也按实际播放的条目写入账号记录。暂停时，只有当前播放的 CID 与原网页相同才更新该网页的进度条；关闭播放器时，使用原网页所属 CID 的最后缓存位置，即使此时正在播放另一个 CID，也不会把另一条目的位置写入原网页。播放中继续保存本机与账号记录，不移动网页进度；换集及片尾不会被当成关闭播放器。详见 [进度同步](./playback-progress.md)。

请保留原网页，后续条目需要它进行账号鉴权解析。关闭网页后当前已经打开的媒体可以继续播放，但后续新条目的解析可能失败；重新打开相同视频页可重新接管列表。失败与超时会释放加载，不让播放器无限等待。关闭进度同步不会关闭列表解析。

刷新网页或从另一个页面接管尚未完成的合集时，会恢复后台补齐并撤销旧页面未提交的上传。后台失败会明确显示“合集加载失败”，保留当前视频播放，不把只含当前 CID 的临时清单声称为完整合集。HTTP 兜底与 WebSocket 都传递就绪／失败通知；需要重新解析时可在原网页重试移交。

### 切换分 P 时反复显示 Retrying

旧版 `portable_config/scripts/ytdl-retry.lua` 会把本机合集条目地址误当成 yt-dlp 网页，在解析或媒体加载失败后显示 `Retrying (n/8)...`，并用单条地址替换整个合集；延迟重试还可能打断刚切换的新分 P。当前源码已排除浏览器中继、禁用 yt-dlp 的条目及带签名参数的媒体直链，普通 yt-dlp 重试也会保留原生列表并在换片后取消。

已有本功能的安装可以单独更新该 Lua 文件，重新打开播放器后生效，无需更换中继或重新导入用户脚本。它修复错误重试与列表丢失；若仍提示“列表视频解析失败”，请保留原网页并重新选择该条目，以便重新解析媒体源。

### 拖动或快退后声音延迟出现

旧加载方式用 `audio-files` 单独打开 B 站 DASH 音轨。按关键帧快退时，视频可能落在请求位置之前，音频却跳到请求位置，形成几秒静音。当前 `web_playlist.lua` 与 `quality-menu.lua` 将浏览器提供的视频和音轨放入同一 EDL 时间线，使跳转与缓存共同处理；合集、单视频和切换画质均使用此方式，原生条目、CID、字幕、续播点和请求头继续保留。

更新这两份 Lua 后重新打开播放器即可，无需重装中继或用户脚本。未提供可选画质列表的 B 站单视频也会合并当前唯一音轨。普通本地外置音轨不受影响。该修改针对 MPV 已确认的[外置音轨快退静音问题](https://github.com/mpv-player/mpv/issues/18369)，使用[官方 EDL 多轨机制](https://github.com/mpv-player/mpv/blob/master/DOCS/edl-mpv.rst#separate-files-for-tracks)，不修改音频延迟或全局跳转快捷键。

## 更新文件

下载累计包 `mpv-lazy-2026-custom-cumulative-update-v2026.10.14.zip` 并用 `SHA256SUMS-v2026.10.14-update.txt` 校验，关闭本安装的 MPV 和中继后合并到 `mpv.exe` 所在目录。包内包括：

- `external_player.js`／`external_player.user.js`（**1.2.14.26**）：导入用户脚本管理器，禁用重复旧版并完整刷新页面。
- `portable_config/scripts/web_playlist.lua`、`web_progress.lua`、`quality-menu.lua`。
- `portable_config/scripts/uosc_danmaku/main.lua`、`sites/bilibili.lua`。
- `portable_config/scripts/uosc/main.lua`、`elements/Menu.lua`、`lib/web_playlist_tree.lua`、`lib/web_playlist_menu.lua`。
- `tools/telegram-web-mpv-bridge/` 内的 EXE、`bridge.py`、`bilibili_danmaku.py`、`playback_progress.py`、`web_playlist.py` 和启动／构建脚本。

继续使用原有 MPV 与 BrowserRelay 注册。列表服务与 B站弹幕／进度共享 `127.0.0.1:9002/9001`；可手动运行 `start_browser_relay.ps1 -WebPlaylist`，`/health` 应包含 `webPlaylistApiVersion: 1`、`webPlaylistHierarchyApiVersion: 1`、`webPlaylistChunkApiVersion: 1` 与 `webPlaylistFastStartApiVersion: 1`。WebSocket 不可用时走匿名扩展 HTTP 轮询。更新后重启旧中继及播放器，再完整刷新网页。

列表不按视频或分 P 的数量截断，通过分块注册、分页恢复及分块 IPC 传递完整元数据。缺失分 P 详情会以最多三个并发请求补齐，已知单 P 不重复请求；明确发现合集或分 P 不完整时会提示。首播复用已经取得的当前 CID `view`／`playurl` 结果，避免为同次移交再次请求相同数据。清单只保存公开内容信息和稳定本机条目地址；签名媒体地址只在解析和播放器内存中使用，Cookie、CSRF 和账号密钥留在浏览器。单视频及其他播放器保留原有交接方式；番剧影视、互动分支和 DRM 媒体没有接入。

传输保留资源保护：每次上传最多 100 个条目并受 48 KiB 预算约束，清单 IPC 每条不超过 32 KiB，每份公开元数据清单预算 32 MiB、最多八个会话。后台扩展沿用同一会话，不额外占一个名额。字节预算与实际发送共用 UTF-8 JSON 序列化，并计算嵌套 JSON 字符串转义后的实际大小。超过预算明确报错，不静默截断成部分合集；这些预算不是视频数量上限。

## 验证

`test_web_playlist.mjs`、`test_web_playlist.py` 与播放列表 Lua 测试覆盖完整层级、分块重试、归属、迟到请求、各项媒体参数和进度隔离。`smoke_test_web_playlist_hierarchy.py` 使用真实 MPV、1001 条目、3 P／4 P 视频，验证单 P 没有子层、当前祖先自动展开、折叠不改变原生列表，以及乱序后点选仍对应正确条目。既有真实 MPV 冒烟继续验证循环和品质切换，测试均使用长模拟签名地址。真实页面范围见对应验证报告。

`test_ytdl_retry_lua.py` 覆盖合集条目及媒体直链不触发通用重试、原生列表重试保留、换片和停止后取消旧回调。`smoke_test_web_playlist.py` 同时加载实际重试脚本，注入解析失败与媒体 404，并检查原生列表和下一分 P 不受延迟重试影响。

给上述层级冒烟添加 `--fast-start`，会先启动一个当前条目，再在同一实例扩展到完整清单，并检查当前原生 ID、播放位置、暂停、品质与轨道没有因扩展而重载。运行方法见 [发布验证说明](../../tools/release/README.md#完整合集层级与-1001-条目验证)。最新快启与清理范围见 [2026-10-14 报告](../reports/2026-10-14-cleanup-and-fast-start.md)；`.21` 的既有真实合集验证保留在 [2026-10-13 报告](../reports/2026-10-13-web-playlist-hierarchy.md)。

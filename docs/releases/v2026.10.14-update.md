## 本次整合的新列表与快启

- **完整合集和全部分 P**：普通 BV／av 视频属于合集时交接完整合集及各视频的全部 P；不属于合集时交接当前投稿全部 P。从网页当前选中的具体 P 开始。视频和分 P 的数量没有“两条”或“500 条”的任意截断。
- **按网页结构显示**：播放器列表按“合集／分节 → 视频 → 分 P”展开。多 P 视频可展开／收起；单 P 视频直接显示为可播放项。当前祖先自动展开，其余折叠选择保留，折叠不删除原生条目。
- **原生播放模式**：顺序及列表循环遍历完整合集和各 P，乱序以具体 P 为单位，单曲循环播放当前 P。点击菜单项使用原生条目 ID，避免乱序或重排后选错条目。
- **后续条目按需解析**：打开下一条时由原网页重新取得源，保留实际可用品质、独立音轨、字幕和对应 CID 的弹幕；切画质保留播放列表、位置及暂停状态，各条目分别保存续播与账号历史。需要保留原网页供后续解析。
- **大合集先播再补齐**：当前 CID 的源与单条启动列表就绪后立即启动播放器，后台最多三个并发请求补齐完整合集，再扩展同一个原生列表，保留当前条目 ID、位置、暂停、画质、音轨和弹幕，不重载当前视频。
- **减少重复解析**：复用首播已有的元数据和播放源，后台通过轻量分 P 接口取得页数组，不为每个视频重复下载整份合集。校验连续页序、唯一 CID 及已知分 P；缺失或失败明确报错，不将不完整清单冒充完整合集。
- **传输与恢复**：分块注册、分页恢复和分块 IPC 支持大列表；单份公开元数据预算 32 MiB，最多八个会话。刷新页面后恢复后台补齐，HTTP 与 WebSocket 都通知合集完成／失败，加载中或失败会显示在列表面板。

详情见 [网页播放列表](https://github.com/HikigayaMan/mpv-lazy-2026-custom/blob/v2026.10.14-update/docs/scripts/web-playlist.md)。

## 新的进度同步规则

网页观看后移交 MPV／MPVNET，从当前网页或最近保存的位置续播。本机续播与 B站账号历史继续记录播放器的位置，但 **MPV 播放中不再持续移动原网页的播放条**。

| 操作 | 原网页位置 | 本机续播／账号历史 |
|---|---|---|
| MPV 播放、恢复播放、播放中拖动 | 保持原位置 | 继续保存实际位置 |
| MPV 暂停或暂停中拖动 | 更新为对应暂停位置 | 保存新位置 |
| 快速暂停后立即继续 | 保留暂停时的更新，恢复后不追加跳转 | 继续保存 |
| 正常关闭 MPV | 更新为退出快照／最近成功采样位置 | 保存，手动退出不误标完成 |
| 片尾、换集、循环、品质重载 | 不作为关闭，不因此移动原网页 | 按对应视频／分 P 保存，实际看完才标记完成 |
| 用户主动在网页播放或拖动 | 网页接管记录控制权 | 保存网页实际观看位置 |

- B站普通 BV／av 及分 P 按 `aid + cid` 分开记录；倒退和零秒按最新操作保存，品质切换加载中的临时零秒不抹掉位置。
- 账号历史通过原网页登录状态写入，约 15 秒一次，与网页播放条更新分开处理。Cookie、CSRF 和 WBI 密钥只留在浏览器，不发给中继。
- 网页刷新、DOM 替换或中继重连不会回放正在播放的 MPV 缓存位置。修复冷启动注册、初始化慢请求及站点自动恢复位置误接管，保留实际点击、拖动与快捷键的网页接管能力。
- Lua 保留暂停边界，HTTP 合并普通采样时也保留暂停事件，避免短暂停后继续导致暂停更新丢失；WebSocket 使用相同规则。
- 原网页关闭后中继仍保存本机位置；账号历史需要登录网页保持打开。普通有限时长网页视频支持本机续播，直播、番剧影视和互动分支不套用点播续播。
- 双向进度和账号历史默认开启，可在网页设置中分别关闭。正常采样间隔约 1 秒；IPC 先关闭或进程被强制结束时，最近采样可能与最后一帧有差异。

详情见 [进度同步](https://github.com/HikigayaMan/mpv-lazy-2026-custom/blob/v2026.10.14-update/docs/scripts/playback-progress.md)。

## 累计包含的弹幕、品质与播放器改进

- **B站直播实时弹幕**：网页移交时创建独立 Windows IPC 弹幕会话，支持短房间号、iframe／资源嗅探、心跳、重连、认证刷新和退出清理。暂停或切流加载期间丢弃消息，恢复后显示新弹幕，隐藏弹幕保留连接。失败说明阶段及原因，不阻止视频继续播放。
- **表情作为文本**：文字消息保留 `[dog]` 等标签；图片表情显示其名称，无名称使用 `[表情]`，不显示图片链接或下载表情图片。礼物／系统广播不作为文字弹幕。
- **点播与直播弹幕统一**：共用开关、粗体、字号、描边、阴影、速度、透明度、区域和帧率；首次默认显示，明确关闭后继续保留。普通视频已加载弹幕可按新样式重新排布，暂停时也能刷新；旧 `b` 入口转交统一插件。
- **清晰度与流品质菜单**：交接账号实际可用的档位、编码及音视频信息，默认最高可用，保留用户明确的低档选择；修复菜单一直转圈，失败或超时结束等待并提示。点播切换保留音轨、位置和暂停，同房间直播切换保留弹幕会话与显示开关。
- **同画质备用源**：优先使用 B站 API 返回的标准 HTTPS `bilivideo.com` 备用源，修复部分特殊端口 PCDN 主源无法连接，保留画质、编码及签名。
- **设置自动保存**：视频滤镜／补帧／超分、着色器单项与预设、解码与画面调整、弹幕开关与样式在重启或打开普通视频后恢复。清空滤镜／着色器也保存；自动画面预设与临时弹幕滤镜不会误记成用户选择。偏好写入合并其他实例，弹幕样式跨实例同步。
- **网页启动全屏**：移交 MPV／MPVNET 后默认全屏启动，其他播放器遵循各自配置。
- **缓存缩略图**：播放条悬停约 0.2 秒后预览附近关键帧。网络视频只导出 MPV 已缓存范围，不额外请求原视频 URL、不改变播放位置或暂停；未缓存位置清图并提示，切换、缓存驱逐或任务过期时清理。按钮及快捷键统一控制 `thumb_engine`。
- **自动移交默认播放器**：可选进入视频／直播网页后自动启动已启用的默认播放器，默认关闭。识别新视频、分 P 和直播间，过滤同内容重复通知；解析失败可手动重试，浏览器外部协议确认仍由浏览器控制。
- **重复项与故障清理**：移除 15 条重复按键定义并保持最终生效命令；ArtCNN 旧入口共用实现。修复品质重载迟到回调、普通视频 CID 查询空回调、初始 UI 尚未就绪及含引号／反斜杠弹幕的 IPC 字节预算问题，保留原有功能入口和用户数据。
- **构建与诊断**：增加会话失败阶段、脚本／Lua／中继回归及真实 MPV 冒烟工具；累计包附源提交、逐文件哈希、完整累计差异和 EXE 构建输入／验证信息。

完整功能、配置路径及边界见 [README](https://github.com/HikigayaMan/mpv-lazy-2026-custom/blob/v2026.10.14-update/README.MD#相比原仓库的全部功能更新)。

## 使用边界

品质以账号实际权限及接口返回为限，签名直链过期需刷新网页。后续列表源解析与账号历史需要原网页；直播认证刷新也可能需要网页保持打开。缓存预览依赖完整缓存包且采用附近关键帧，无法封装／解码时可能暂不显示。进度更新、账号历史及退出采样受网络与程序退出时序影响。本包保留原项目 AI／RIFE 等功能，但相关模型与硬件依赖仍需用户原有可运行环境。

源码差异见 [原仓库基线至本次版本](https://github.com/HikigayaMan/mpv-lazy-2026-custom/compare/547e3d7f7a1aa44538ab55fdba3a36e5bcb61984...v2026.10.14-update)。各文件按其许可证与原作者声明使用，许可及中继 EXE 第三方说明随包提供。
